# GHOSTBBS — structure steering

```
/
  index.html
  vite.config.ts            base: './' so the build runs from any static path
  src/
    main.tsx                React root only
    ui/                     screens + components (no game rules)
      App.tsx               screen state machine: boot -> login -> menu -> door -> result
      Boot.tsx              modem handshake
      Menu.tsx              main menu + about + message board
      DoorGame.tsx          the playable grid
      Board.tsx             renders the grid + HUD
      ResultCard.tsx        score, share text, copy button, leaderboard
      styles.css            the only stylesheet
    game/                   pure, DOM-free TypeScript
      daily.ts              date helpers, seeded RNG, level generation, BFS par
      engine.ts             move application, spectre logic, scoring, share text
      storage.ts            localStorage wrappers (handle, run, scores)
      types.ts              shared types
  tests/                    vitest specs for src/game
  .kiro/
    specs/ghostbbs/         requirements.md, design.md, tasks.md (generated by Kiro)
    steering/               product.md, tech.md, structure.md
    hooks/                  post-save typecheck hook (+ its execution log)
  docs/                     screenshots used by the README
```

Rules:
- Keep `src/game` importable by Node/Vitest with no DOM types in signatures.
- One component per file; props typed inline; no default exports except `App`.
- If a file grows past ~200 lines, split it rather than adding another concern.
- Do not add dependencies without a note in the README explaining why.
